这是中文电商搜索数据，不是现成的文本聚类或用户意图金标。论文称 Lite 按用户抽样，保留连续一个月内的完整搜索与互动，规模为 102,086 users、555,553 queries、6,634,118 products；不等同于独立抽取少量请求。完整数据的 Relevance 规格为 46,422 query–item pairs，不能将其算作 Lite 的聚类样本数。

|---|---|---:|---|
| Relevance | `relevance/` | 15,827,789 | 专家标注的 query–item 相关性 0–3；0 无关、3 高度相关；不是簇 ID |
| Lite recall | `recall_lite/` | 257,794,992 | 搜索请求，含 query、session、相对时间和曝光/点击/购买商品列表 |

## 时间与许可边界

论文 Table 2 与 Appendix B 仅确认 `time index` 为去标识化的**相对时间索引**。本次查阅来源未确认秒/毫秒等单位、跨用户时间原点是否一致、并列时间事件的顺序或真实日历映射。不得据此直接宣称可作精确实时/全局日历回放；需先审计单位、粒度、排序及特征的时点可用性。

## 值得验证的问题及准入门槛

- Relevance 可作低体量的语义匹配/细粒度相关性辅助诊断；不能直接以 0–3 分数当文本聚类标签。
- 商品标题聚类可探索类目导航，但需明确 L1/L2/L3 粒度、类目一致性、重复商品/卖家泄漏和文本含标签信息；不将类目一致性冒充用户意图质量。
- Lite recall 可探索 query 聚类与搜索会话的时序一致性；曝光/点击/购买是行为监督，不是用户真实意图金标，也不是整个站点的完整曝光。
- 准入顺序：澄清许可与 provenance → 固定 revision/hash 与必要字段 → 检查关联键、重复/切分泄漏、时间与标签定义 → 预登记任务及预算。统计特征必须验证是否含未来信息。
