## 后续每篇新增的最小卡片

正式来源与版本 → 任务与输入假设 → 已知/未知 K 与监督 → 数据与切分 → 核心结果及表号 → 代码/权重/许可/核对日期 → 成本 → 对现有基线的新增价值 → 能证伪它的最小实验。

仅新增 BibTeX 不算覆盖完成。每轮优先补“有书目但无证据卡”的核心条目，以及数据集可重建性；避免把重复预印本/会议版和共享软件 stars 重复计数。更新日期、来源检查与实验状态必须分开。

## 语义对照的下一道门槛

[semantic-pilot-v1 执行协议](../experiments/semantic-pilot-v1/README.md) 与 [实际结果](../results/semantic-pilot-v1/README.md) 已落地：独立 CPU 环境、固定 E5-small revision、双语 `query: ` 前缀、池化/归一化和 512 条/角色的无标签抽样，全部本地推理。原 preparation-only preflight 保留作历史记录，不再作为阻塞状态。

词面与语义使用同一批样本；oracle-K、固定未知 K、仅 validation 选参的未知-test-K 三种预算分开。小样本只检验流程，不作全量性能或稀有意图结论；向量优于词面的 oracle-K 结果不等于未知 K 的密度发现也改善。后续扩展不覆盖既有分数，而以明确版本和协议建立新结果。

<details>
<summary>ⓘ 新版内存测量和比较边界</summary>

每种策略每轮使用全新 worker，不读取源文本，也不加载编码器。输入 mmap 全量触页、相同数值 API 预热后设基线（约 163 MiB）；表中是 warmup／预测／更新阶段采样峰值减去此基线。文件与共享页、匿名 RSS、绝对 RSS、重建时双树共存及末态序列化分开记录。序列化仅含 BIRCH 估计器；rolling 另有至少 3 MiB 数值回放缓存和控制状态，已包含于 RSS，不是完整重启文件大小。这比 v1 更隔离，但增量仍含分配器保留、工作空间和采样开销，不是算法独占堆内存。

采样间隔名义为 5ms，并在阶段边界与双树共存点同步采样；调度可能延迟，短暂峰值可能漏掉，不能据此承诺不会 OOM。时间包含采样与重建，不含源准备、编码、热身和预测，不能跨版本比较速度。相同输入和导入条件下比较两轮结果；不跨任务排总榜。

**跨日故事再次出现很少，不能当作新话题检测。** 核对缓存哈希及已提交 v1 预检后，v1 是 2 / 597 个 STORY-日再次出现、3 / 3,584 条对应记录；v2 是 3 / 1,807 个 STORY-日、5 / 11,776 条记录，涉及 3 个不同 STORY。这里“再次出现”仅指在已选热身或此前已选日期见过；3 个均来自此前测试日期，热身交集为零。STORY-日逐日计数，不等于全期不同 STORY 数（v2 为 1,804）。首见标题评分保留相同原始历史：v2 为 3 / 1,800 个 STORY-日、4 / 11,685 条记录。详细日期及 v1 首见标题分母见[审计说明](../results/calendar-paired-v2/README.md)。抽样历史中未见不等于语义新颖，跨日见过也不等于消失后重现；日内 ARI 不能代替校准误报的新话题检测或跨窗身份保留。

前一周已在 v1 看过，延长窗口是预登记续跑而非全新盲测；确定性复跑也不是统计置信区间。下一步可在独立时段复核，并单独研究重建时的内存回收策略，不根据这里的分数回调本轮参数。


可参考 [Synthetic Fire Drill](../references/milev2026syntheticfiredrill/README.md) 的受控注入思路，分别观察被旧簇吸收、形成新簇及校准后的误报；只列为固定嵌入空间的压力测试参考，尚未在本库复现。背景新闻原文未公开，不能据此承诺原文重编码／端到端复跑，也不能把同一批行机械重放当作自然重现证据或汇入跨任务总榜。

</details>

## 层级归属：叶节点未知，不等于父节点未知

**已实测 · hierarchy-e5-v1：已知叶误拒率 57.4%，父级增益小且不一致。** 固定验证集阈值后，测试中拒出 89 / 104 个隐藏叶查询，却也误拒 132 / 230 个已知叶查询；已知覆盖率仅 98 / 230（42.6%）。父级均值方案只多判对 2 / 104，不能因接收子集准确率高而忽略误拒成本。

<details>
<summary>ⓘ 层级实测的覆盖率、宏平均与比较边界</summary>

两方案共享同一 E5 表示、已知叶原型、叶预测和拒识掩码；父均值对归一化叶原型等权，不按支持行数加权，也不按查询重排候选。阈值规则在首次评分前锁定，只用验证集已知／隐藏标记最大化平衡正确率；无测试调参、无全局 oracle K。两次复跑预测及非资源字段完全一致。

全体隐藏查询的父类宏平均为 .615385 → .634615，联合宏平均 .471154 → .490385；每个测试隐藏父类恰有 8 条查询，因此这里宏平均与逐行比例相同，并非第二份独立证据。拒出子集父级正确是 49 / 89 → 51 / 89。已知叶接收后准确率 93 / 98（94.9%），但覆盖率只有 98 / 230，接收且叶正确仅 93 / 230；单／多子叶已知查询分母和验证集结果均在独立报告。

这是有监督已知拓扑上的父级归属，不是发现父类、创建新节点、自然流新意图检测或业务增益。与原 42 个静态／路由运行、历史层级场景及日历维护试验分开，不混用旧分数。预检保留原始记录，新结果另列 hierarchy-e5-v1。

</details>

MASSIVE zh-CN 的 scenario/intent 可作两层公开试验，但官方 intent 名称会泄露父类。层级输入只能给**不透明节点编号、已知叶的父子边、支持样本及原始 `utt`**；名称、带槽位文本、隐藏叶及其映射不参与决策。评价使用官方标注，不代表发现、命名或插入新节点。

平面路由原协议允许整个父类不在支持集，适合测拒识，不适合把其正确父类计作可达。层级试验应单列两种问题：

- **未见叶、父类可达**：每个隐藏叶在训练支持集里有同父兄弟。验证、测试隐藏叶互斥；只用验证集设阈值。先比「最相近的已知叶映射到父类」与「直接比较等叶权重的父类原型」，保持输入与标签预算相同。并列全体隐藏叶的父类命中、成功拒叶且命中父类、已知叶覆盖与准确率，不能只看被接收子集。
- **父类不可达**：父节点不在候选集中，单列拒绝或复核率和错接已知父类率；这里不报可达父类命中。若引入描述、外部 taxonomy、节点生成或 LLM，明确额外信息和独立协议。

[层级切分的数据与接口预检](../experiments/hierarchy-preflight-v1/README.md)已用固定 MASSIVE 数据验证：18 个父类都有实际支持，13 个测试隐藏叶（与验证隐藏叶互斥）、104 条隐藏测试行，没有跨角色的规范化文本重合。该历史预检本身只核验可达性、样本与方法输入，不含模型结果；上面的 hierarchy-e5-v1 独立完成首次 E5 父级归属评估，仍未测新节点质量。
